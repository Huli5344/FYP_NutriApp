There is no permission matrix, because there are no tiers

This panel was first written against a three-role model — free user, paid user, administrator — with a row per permission. This project has no paid tier and no per-feature permissions: there are accounts, and some of them have the administrator flag. Every feature in the app is available to every account.

A matrix is shown here only when one exists. Displaying fourteen rows of Yes and No describing a system that was never built would read as documentation, and the first person to rely on it would be relying on nothing.

Granting the first administrator

A freshly deployed database has no administrators, so this panel is reachable by nobody — which is the right starting state. The first one is granted from the command line with tools/make_admin.py; after that, administrators can promote each other from a user's page. The last remaining administrator cannot be demoted here, because that would close the panel on everyone.
